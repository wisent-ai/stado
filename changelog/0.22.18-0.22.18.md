# Changelog 0.22.18 – 0.22.18

Released entries, moved out of `CHANGELOG.md` so that file stays editable.
The current entries live there; this file is history and does not grow.

## 0.22.18

- On macOS, available memory is the kernel's own `kern.memorystatus_level` share of `hw.memsize` (what `memory_pressure` prints as the free percentage), in the host's memory pass, in `stado space report` over the host channel and in the runner diagnostics. The three readers summed only free, speculative and purgeable pages and left out the cache the kernel reclaims, so lukasz-macbook published 0.7 GiB available against its 4 GiB watermark while the kernel's level read 71% of 64 GiB (be303300).

## 0.22.18

- A handoff made after a build froze its batch, whose commit that build contains, is bound to it in an additional batch `runs/build/<build id>/changes-<digest>.json` the next time the build is submitted, and reads that build's verdict. It used to stay `queued` for good: every `stado build newest --queued` picked the product again and answered with the same passed build (tama 5654e49f on 2026-09-30) (c187756d).

## 0.22.18

- A worker claims one release build per build cache at a time. A build job whose product and platform share their Cargo target directory with a build already running on that host stays queued, and the scan publishes it under `claim_declined` with the reason, which `stado host gates` prints as a `declined:` line. On 2026-09-30 lukasz-macbook claimed three Stado darwin builds at once and the newest sat 42 minutes in `Blocking waiting for file lock on build directory` inside a claimed slot (03351f2b).

## 0.22.18

- A new build cancels the product's older builds it supersedes. After `stado build submit` or `stado build newest` queues a build, the jobs of every older build of that product still `waiting` whose commit is an ancestor of the new one are cancelled on each platform the new build queued, one stderr line each. On 2026-09-30 build 652b6c96 (c6a63931) compiled for over 77 minutes after 03baf850 (063d095f, a descendant) was queued, holding the Cargo lock the new build waited on (28f4a7af).
