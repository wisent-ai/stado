# Changelog 0.23.68 (part 10 of 10)

Released entries, moved out of `CHANGELOG.md` so that file stays editable.
The current entries live there; this file is history and does not grow.

## 0.23.68

### Changed

- **`stado product remove PRODUCT...` uninstalls whole products in one command:** removing a
  product took one `--surface` per call, so uninstalling Tama, Stado and Oko meant knowing which
  of `cli`, `desktop` and `service` each had installed and running `remove` once for each.
  Without `--surface`, `remove` now takes one or more products, reads every receipt under
  `~/.stado/products/<product>/` and removes each surface recorded as installed (service, then
  desktop, then CLI) through the same removal that `--surface` runs, with the same ownership
  checks and backups; the product whose installation placed the running `stado` goes last. A
  product with no installed surface is refused with `<product> has no installed surface on this
  machine: no receipt under <home>/.stado/products/<product> records one`, a product named twice
  is refused before anything is removed, a failed removal names the products already removed,
  and a missing receipt for a named surface now names its path. Stado Desktop's Products screen
  has the same operation as *Uninstall products*.
- **`stado product create` refuses to create what already exists:** a creation request was
  checked only for a catalog product with the same id, so an existing repository proposed under
  a new name went through as a "new" product. Before the first repository is provisioned, the
  request is now held against every repository the catalog claims and every repository each
  requested owner already holds on GitHub (the list `stado product catalog --unclaimed` reads),
  and refused, naming the repository and the product that claims it, when a requested
  repository exists or the product id is the name of an existing repository. A repository the
  same request provisioned on an earlier run is its own, so `--resume` still works.
- **Stado's roadmap names OpenRouter as a way to sell tokens:** the catalog's roadmap for Stado
  carries *Become an inference provider on OpenRouter*, and `/docs/earning` says what it needs.
- **`stado web origin declare` defaults to our own publication:** with no `--publication`, a
  public origin was declared `tailscale-funnel`, so the default way to make a fleet name public
  depended on an outside network provider's control plane. The default is now `web-edge`, which
  publishes through the `stado web` declaration that owns the hostname on the fleet's own
  declared edge. `tailscale-funnel` is still accepted when it is named.
- **The database client's cancellation reaches every engine's connect:** `connect_cancellable`
  passed the caller's cancellation to the credential resolver and to the Postgres pool, but a
  MySQL or SQLite pool connect still waited without it. Every engine's pool now opens through
  one wait that honours the cancellation and refuses with the step and `czekanie odwolane`.
- **`stado doctor` names why the release manifest could not be fetched:** the release channel
  check reported reqwest's own `error sending request for url (...)`, which hides why TLS or the
  connection failed. It now names the stage (`connecting or the TLS handshake failed`, `the
  request timed out`, `the request failed after it was sent`) and the whole chain of causes,
  such as an unknown certificate issuer, an expired or mismatched certificate, or a refused
  connection.

- **`stado sandbox fleet` places and finds sandboxes across the fleet without `--host`:** every
  fleet sandbox operation named its host, so work went where the caller pinned it, not where
  there was room. `--host` is now optional on every operation but `inventory`. `create` reads
  every registered Linux host at once with one read-only program (gVisor `runsc`, cgroup v2,
  `--nvproxy`, `nproc`, `MemAvailable`, `MemTotal`, NVIDIA GPUs, and the limits its running
  fleet sandboxes hold) and puts the sandbox on a host with the declared cores, RAM and GPUs
  free, the one with the most free RAM first; every named operation runs on the host that keeps
  the sandbox; `list` lists every host's sandboxes with their host. A name is kept unique across
  the fleet, a host that cannot be read is named and does not stop the others, and the receipt
  carries `placement` with the verdict on each host; no host with room is refused naming every
  host and why. Stado Desktop's Fleet sandboxes take the host as optional.
- **`stado product install` installs a Cargo surface again:** planning prerequisites read every
  recipe's `manifest` as a release manifest, so a Cargo installation's `Cargo.toml` was parsed
  as JSON and each install or `--plan` of one was refused with `parsing release manifest
  most-rs/Cargo.toml … expected value at line 1 column 2` (Most's service, Skrzynka, Skryba and
  every other Cargo recipe). Only a Stado release's manifest is read for verb contracts now; a
  recipe of another kind declares no verbs.
- **A unit holding an option a later build removed no longer blocks every upgrade:** a newer
  Stado read each running `stado serve` unit's argument vector with its own parser, so a unit
  rendered by an older build with an option since removed (`--disk-cleanup`) was refused as
  `cannot be read by this build's serve: unexpected argument`, `product update stado` could not
  retire it (`the units stado replaces could not be read, so none was retired`) and the host
  could never be upgraded. The serve line is now read from the options this build declares;
  an option it does not declare is set aside with its value as opaque text, read as no role, and
  `host` role reports name it on stderr. A line that still does not parse is refused as before.
- **Product sync installs again after a writer left `sync.lock` unreadable:** sync wrote a
  second record over the lock's own and could leave zero bytes before it, which refused every
  later pass; it now keeps only the lock's record, and a free lock whose record cannot be read is
  reclaimed with the cause on stderr.
- **`stado serve`'s product sync runs each pass as a child process** with `~/.stado/bin` and
  `~/.local/bin` ahead of the unit's path, so what an installation placed there reads as ready.
- **An installation without a coordinate builds the revision it chose for every recipe:** a
  recipe that builds its checkout's commit (`local-build`, `npm`, `cargo`, desktop) was refused
  as if `--source-commit` had been given; it now builds when the checkout stands on the chosen
  revision and names the checkout and both commits otherwise.
- **A running `cargo` build keeps its build directory.** The janitor's guard locked only
  `.cargo-lock`, but a Cargo build-dir laid out apart from the artifacts is held through
  `.cargo-build-lock` (and a target through `.cargo-artifact-lock`), so a pass took directories
  running builds were compiling into. The guard now locks all three and keeps a directory any of
  them is held in (`held_by_build`).
- **The Xcode and package-cache cleaners read what holds a tree right before taking it,** under
  the cleanup lock, so a build started after the pass began is seen; a directory entry that cannot
  be read is reported, not skipped silently.
- **The crash-loop defect hand-off to Oko states how a caller meets it (`--blocks-nothing`),** which
  Oko had refused on every pass since it began requiring it. A host without Oko says `Oko not
  installed` once per loop instead of failing every pass, and the operator's page goes out either
  way.
- **Enrollment refuses a request's form before reading anything:** a name that is not a lowercase
  target identifier, an `--ssh` destination ssh would read as an option, and a `--kind` nobody
  declares are refused with exit 2; `approve` refuses a fleet nobody declared before writing.
- **A stored join request that is not JSON is `config`, exit 1,** not a retryable outage (exit 69):
  retrying never repairs it; `stado fleet reject` and a new `join` do.
- **A candidate left running by a pass that is gone is resumed and named:** a pass records itself
  on the candidate it carries; a running candidate whose repository's pass lock is free (the lock
  the kernel releases when the pass's process ends, killed or not) is listed as `waits on: a pass;
  the pass that carried it (pid N) is gone …`, and the next pass resumes it.
- **The resident pass asks Oko as the fleet's daily build:** a pass under no agent session asks
  `oko admit compile|test` with no session first, the run the operator's `@fleet-budget` consents
  admit, then as the submitter's work; its refusal names the subject that would admit it
  (`<action>:<product>@fleet-budget`). A pass inside a session still asks as the submitter only and
  says so.
- **A fleet store that does not answer no longer stops the queue's gates:** when the hosts'
  capacity publications cannot be read, this host runs the gates of its own platform and the
  registry's hosts of the other platforms run theirs unjudged, each said with the store's error, so
  a repair of the fleet store can land through the queue.
- **A candidate stacked on a waiting candidate is measured over it:** `stado change submit`
  measured a commit's size from its merge base with `main`, so a change stacked on a queued one was
  refused for the lines below it, which that candidate had already been measured for. A commit
  that holds a queued or running candidate's commit `main` does not is now measured past the
  nearest such candidate, and the refusal names it: `<commit> changes <n> lines in <m> files past
  candidate <id> it is stacked on (<its commit>), more than …`.
- **A round recorded during a pass lands its candidate in that pass:** a pass that held a
  candidate for its review round went on to the candidates behind it and ended, so a round a
  reviewer recorded meanwhile waited for the next pass. Before it ends, a pass now reads the rounds
  again over each candidate it held for review and takes again those that have one (`<id> has a
  review round over the tree it lands, recorded after this pass held it; this pass takes it
  again`).
- **`stado change status` judges the recorded rounds:** a candidate held for its review repeated
  the last pass's `waits on: a review round …` after a round was recorded. It now reads the rounds
  over the tree the next pass lands: `waits on: the next pass of the queue, which lands it: …` when
  they found nothing, `… which refuses it: <each finding> …` when one found something, and the
  review command only while none is recorded.
- **A model request is handed to Stado, and Brama's alternative is a statement recorded for the
  request:** a product resolved `inference`, then dialled what it was handed itself, reading the
  endpoint's key and choosing whether to sign, so every alternative added to the catalog needed a
  change in every product. `stado capabilities call inference --consumer C [--json]` takes the
  OpenAI chat-completions request on standard input, asks the first alternative in the selected
  order that answers it and prints that answer; one that cannot answer this request is named with
  its cause and the next is asked. Brama is sent the request with the `token` of
  `<consumer>-model-router` and, when an item plays `<consumer>-agent-auth`, its signature. The
  OpenAI-compatible `model-endpoint` alternative and its `capabilities.inference.endpoint.*`
  settings are removed; `attestation` takes its place: a request no alternative before it
  answered is kept under its SHA-256 and refused naming the command that answers it, and
  `stado capabilities attestation list|show|record|revoke inference --consumer C` reads it and
  records the answer with what was checked, answering that exact request as a chat completion
  whose `model` is `attestation`. Stado Desktop runs the same operations on the Compute providers
  screen.
- **Changelog moves share a writer and validate part identities:** empty outlines do not become releases or block submission, and empty linked parts are collected.
  Desktop describes the same operation without copying backend-owned directories and retains the CLI's refusals.
- **A placement move stops an empty copy on its destination:** a destination
  unit already running is refused as a second copy only when the destination
  holds some of the profile's required state; one holding none (a loaded
  standby, like the laptop's Skarbiec with no vault file) is stopped first.
- **`registry doctor` names a `foreign-install-root`:** a release-controlled
  product rooted under one target's home while another target's home differs,
  with the `{home}` form to write through `stado release policy apply`.
- **`placement standby` probes a host where its unit listens:** the probes it
  writes for the new host take the port the directory names for that host
  (else the placed host's port, which the unit then takes), keeping scheme,
  host and path; they were copied verbatim from the placed host, so a host
  the directory already served on another port was probed on a port nothing
  listened on there, and the move's health check judged the wrong service.
- **`placement profile draft` probes from the catalog:** a service drafted
  without `--probe` is probed with the catalog's `answering` request for the
  product its unit runs, when that is a GET with no body, at the address the
  directory names for it on its active host; `--probe` is needed only where
  the catalog declares none. The catalog now declares Weles' `GET /healthz`,
  which the host Stado process also asks on each beacon pass.
- **The product catalog states no number of its own:** the host Stado
  process's beacon period is the value the host's registry entry declares as
  `health_interval_seconds` (`${declared:<field>}` reads any field of the
  target's entry, and a host that declares none is refused naming the field
  and `stado registry set --path targets.<host>.<field> --value <value>`);
  bind addresses are written as `$STADO_LOOPBACK` and `$STADO_ALL_INTERFACES`;
  sources cite files, not line ranges; and the catalog carries no
  `schema_version`, which it only ever compared with itself.
- **A remote registry authority is read once per refresh interval, not once
  per command:** the snapshot a command read is also kept in
  `~/.stado/authority-snapshot.json` (`STADO_AUTHORITY_SNAPSHOT_FILE` moves
  it) until the interval ends, and the next command answers from it, saying
  so on stderr; a registry write forgets it. A registry write to an
  authority whose read was given up less than an interval ago is refused at
  once with that read's sentence instead of standing on the silent host.
  `stado resolver resolve`, the relays and the database plane no longer read
  the authority a second time after the store read: they take this host's
  resolver's held generation or the kept snapshot first. An authority no SSH
  path can reach at all is remembered like a read given up, so the next
  commands in the interval go to their copy at once instead of each standing
  the same connection timeout; the refusal now reads `… a read of it at <time>
  got no snapshot (<cause>), and it is asked again once the <N>s refresh
  interval has passed`. A registry store that is an object API placed on that
  same silent host is not asked either: the read goes to the last-known-good
  copy at once instead of standing the relay's own wait.
- **`stado placement transactions` removes spent move records:** the
  progress records this host keeps of moves the registry no longer holds open
  are removed and named on stderr; a record whose move process still runs is
  kept.
- **Files Stado keeps are found under the same home and written durably:**
  agent grant renewal, release-agent retirement, the owner host password
  read, token custody, onboarding progress, observations, the self-update
  attestation copy, the storage-transaction directory, fleet database REST
  placement, file retirement, image scans and Jeden attachment read the home
  as every other Stado file does (HOME, else the user database), so a unit
  started without HOME no longer refuses; token custody, onboarding progress
  and observations are written whole and flushed with their directory.
- **Token custody no longer bounds a bearer at 4096 bytes:** the bound was
  not Skarbiec's, which reads a fixed token of any length; the bearer is
  verified against its grant's hash as before.
- **Whether a pid is a process is one answer:** local slot admission and
  queue lease owners ask the shared check, so a slot whose process belongs to
  another account is no longer read as gone.
- **`stado resolver status` says what this machine remembers of the
  authority:** `authority not asked: …` while a given-up read stands and
  `authority snapshot kept version=<v> until=<t>` while a kept snapshot
  answers registry reads (`--json`: `authority.remembered`).
- **The object API recovery's readers refuse instead of guessing:** a host
  config that cannot be read, a store prefix that cannot be resolved, a
  non-UTF-8 variable or an unreadable server state is refused naming it;
  relative store, token and state paths are resolved under the home the
  recovery runs as, not launchd's working directory.
- **`stado service env write` and storage-root transactions resolve `$HOME`
  as every Stado file does**, and the storage-root transaction, its rollback
  unit and the release agent refuse a home that is not UTF-8 instead of
  writing it mangled.
- **Report paths are shortened to `~/…` only under the home itself:** a
  sibling directory whose name starts with the home's is printed whole.
- **`stado cost report` reads a job's model the way admission and sizing
  do:** `--model=<value>` is read (it was reported as `=<value>`) and
  `--model-path` no longer counts as a model; a row whose command names none
  carries `model: null` in `--json`, and the run-time medians the local pack
  and the autonomy optimizer use are keyed by the same reading.
- **A placement move transfers and probes at once:** every state of the
  profile is read at once on the fenced source and written at once on the
  destination, and every health probe is read at once after the units start,
  so a profile with several stores or services stands its longest step, not
  their sum; the preflight asks the source's probes, state files and routing
  units each group at once too, `placement standby` delivers every managed
  program at once, and `placement move --authority` hands the promoted
  registry to every other host at once. Each step is still its own timed wait in the
  receipt, and the first failure in the profile's order is the one reported.
  A rollback puts every destination state back at once, and a committed move
  settles every state backup at once. A single-file state
  is streamed through its encoder and decoder instead of being held whole in
  a shell variable or quoted word, so a store of hundreds of megabytes moves,
  and an encoder that fails on the source refuses the read.
- **The config file and Stado's records survive a power loss:** `config
  set`/`unset`, the database and web planes and the identity migration
  replace the config through one writer that keeps its permission bits and
  flushes the file and its directory (`config set` prints `(absent)` for a key
  that was not set); the resolver's published state, its vault consultations,
  held schedules, inference plans, the release agent's rollout state, the
  agent's placement policy, the local credential store, the credential-store
  selector, peer bearers, held repair keys and forward markers are written the
  same way, and no two writers share one fixed temporary name any more. A host
  with no home no longer stops when it would keep a repair key. `stado
  self-update` puts the new binary and its attestation copy in place the same
  way, streamed from the verified file rather than held in memory, so a host
  that loses power after the swap starts the new binary. `stado service file
  fetch` writes the fetched file owner-only from its first byte (its staging
  file was readable by others until a chmod), and the web edge's kept
  Caddyfile and the recovery config install go through the same writer.
- **The Desktop API names the command it does not have:** `POST
  /api/operator/run` reads the command words below the family against the
  CLI's own tree and refuses one that names no command with HTTP 400, `stado
  <words> has no command "<word>"; it declares: <commands>`, before any model
  judgement or run.
- **`stado service list --unowned` and `--undeclared` ask every local host
  at once:** a host that does not answer no longer holds the scan of the
  others; rows keep their order.
- **`stado release status` reads every target's release state at once:**
  each is its own object read, and against a slow store they stood the
  store's wait once per target; the report keeps its order.
- **`stado resolver status` names an authority that reads another host's
  store:** a host that is the registry authority by its own copy while its
  registry store is an object API placed on another host gets a blocker
  naming both, the state a takeover leaves until the object API moves too.
- **Units and paths on a host use the home that host states:** `placement
  standby`'s release-control declaration, `service ensure`'s rendered unit
  and acquisition scopes, the reconciler's repaired unit, and the unit file
  of a catalog product just ensured take `$HOME` from the host's own shell,
  read over its channel, instead of `/Users/<ssh user>` or `/home/<ssh
  user>`; a host that states none is refused as unreachable.
- **A move to a host the profile does not name says how to add it:** the
  refusal now ends `prepare it with stado placement standby <profile> --host
  <host> --reason <why>`, for `placement move`, its `--check` and `evacuate`.
- **A placement move no longer carries the fleet vault past its owner key:**
  `placement move` and `placement evacuate` refuse the profile carrying
  Skarbiec, naming `credentials vault move`, which rotates the owner first
  and passes `--vault-owner-rotated` to the move it runs.

### Removed

- `stado host run build`: `stado host cargo … build` replaces it. The old verb compiled with the
  host's default rustup toolchain, because rustup reads the toolchain from the directory it starts
  in and never from `--manifest-path`. It also left the export, delivery and cleanup to the caller.
