## Unreleased

### Added

- **`stado release history` rewrites a checkout's unpushed commits by a plan:** a push review refuses format-only commits, fixups, commits that take back what another swept in and messages their patch does not match, and each was repaired by hand in a checkout other work shares. The plan names every unpushed commit once as `pick`, `reword`, `fold`, `drop` or `split` (by path); the new commits are made in a private index inside the git directory, the branch moves by compare-and-swap only when the new history keeps `HEAD`'s tree, the working tree and index stay as they were, and with `--notes-ref` an unaltered commit keeps its note while every other is listed as needing its own. Stado Desktop's release operations run the same command. Real test: `cargo test --test release-history`.

- **`stado sandbox` drives Boat sandboxes directly, as an agent does:** `list`, `show`, `create [--ttl-seconds] [--no-env]`, `exec <id> [--cwd] '<command line>'`, `read <id> <path> --encoding`, `write <id> <path> --from <file> --encoding`, `fork`, `stop`, `resume` and `delete`, each one Boat Public API v1 call through the boat provider's own client and settings, printed as JSON. A command that does not succeed fails `exec` naming its exit code, signal or limit; a refusal Boat answered keeps its status, code and request id as the error's details, reported `not_found` for a sandbox Boat does not hold. Stado Desktop's Compute providers screen has the same operations under Sandboxes.
- **`stado sandbox` covers what an agent does in a sandbox besides its life:** `update <id> [--name] [--ttl-seconds | --no-auto-stop]` renames it or changes or clears when it stops by itself; `prompt <id> '<prompt>' --provider [--model] [--reasoning-effort]` hands its coding agent a prompt and `prompt-status <id> <prompt-id>` reads the run; `interrupt` stops every conversation in it; `events <id> --sort asc|desc [--cursor] [--type]` prints one page of its events with the next cursor; `ssh-key <id> --public-key-file` allows an OpenSSH key; `download <id> <path> --to <file>` writes a file or folder into a new local file and refuses one that exists. An option given with an empty value is refused by name rather than sent as absent. Stado Desktop's Sandboxes section has the same operations.
- **`stado sandbox` keeps a sandbox's disk as a template and gives its ports public URLs:** `snapshot save <id> <name>` freezes a sandbox's disk under a name (Boat saves it in the background, its status turning `ready` or `failed`), `snapshot list`, `snapshot show <name>` and `snapshot delete <name>` read and remove named snapshots, and `create --from <name>` starts a new sandbox from one; `host <id> <port> [--public] [--localhost]` gives a port inside the sandbox a stable HTTPS URL, carrying its access token unless `--public`. A name is sent as one URL path segment, so it cannot address another resource. Stado Desktop's Sandboxes section has the same operations.
- **`stado sandbox` runs long commands in the background and reports cost:** `exec --detach` starts a command line in the background and prints its process id at once, instead of waiting for Boat's limit on a command; `process status <id> <process>` reads whether it runs, its exit code and its recent log, and `process stop <id> <process>` stops it; `usage <id>` prints what the sandbox has run and cost. Stado Desktop's Sandboxes section has the same operations.
- **`stado sandbox` steers a working agent and shows the desktop:** `steer <id> '<instruction>' [--conversation <id>]` gives the coding agent's running turn an extra instruction without stopping it, and `desktop <id>` prints the URL that streams the sandbox's desktop, which carries a secret. Stado Desktop's Sandboxes section has the same operations.
- **`stado sandbox` takes files back out of a sandbox's snapshots, also while it is stopped:** `snapshot history <id>` lists every snapshot of a sandbox's disk, `snapshot latest <id>` shows the one resume and fork start from, `snapshot tree <snapshot>` lists the files a snapshot holds with their sizes, and `snapshot get <snapshot> <path> --to <file>` writes a file, or a folder as a tar, into a new local file and refuses one that exists. A snapshot id is sent as one URL path segment. Stado Desktop's Sandboxes section has the same operations.
- **`stado sandbox environment` sets up what every new sandbox starts with:** `list`, `create <name>`, `delete`, `set-var <environment> <key>` (the value is the one line on standard input, so it never stands on a command line; an empty or multi-line value is refused), `rm-var`, `set-file <environment> <path> --from <file>`, `rm-file` and `add-repo <environment> <repository> [--base-branch]` manage Boat environments, and `create --environment <id>` starts a sandbox with one. An environment change answers `success=true` rather than `ok` and a type, which the Boat transport now reads as such. Stado Desktop's Sandboxes section has the same operations.
- **`stado sandbox` recovers a stuck sandbox, forces a stop and shares one:** `recover <id>` power-cycles the machine of a sandbox that stopped answering without touching its disk, and Boat's refusal (`sandbox_is_reachable`, `too_soon`, `no_machine`, `recover_unsupported`) is kept with its code; `stop <id> --force` stops a sandbox whose disk save keeps failing, keeping its last successful snapshot and losing what was written since; `share <id>` lets every member of the organization paying for it use it and wipes the creator's logins from it at its next start, printing `restartRequired` while a running sandbox still holds them. Sharing answers without Boat's `ok` and type, which the transport reads as such. Stado Desktop's Sandboxes section has the same operations.
- **`stado sandbox` reads what ran in a sandbox, also while it is stopped:** `conversations <id>` lists its agent conversations with the one a prompt would continue marked current; `history <id> [--mode sync,stream,detached,process,commands] [--query <text>] [--limit <n>] [--cursor <next>]` prints one page of the commands and other processes that ran in it, newest first; `command <id> <command id>` prints one of them; `logs <id> <command id> --stream stdout|stderr --encoding utf8|base64 [--offset <next>]` reads its stored output from an offset, with `nextOffset` and `done` to read on; and `processes <id>` lists its processes, busiest first, or the last sample Boat kept of a stopped one. An empty `--query` or `--cursor` is refused by name. Stado Desktop's Sandboxes section has the same operations.
- **`stado sandbox file-url` moves files of any size without the key:** `file-url <id> <path> --method download|upload [--ttl-seconds <n>]` prints a short-lived URL the sandbox serves itself for that one file; a plain GET of a download URL gives the file whole and a plain PUT of the bytes to an upload URL writes it, replacing an existing file only once the upload completes. The URL is a secret until it expires; without `--ttl-seconds` Boat chooses its lifetime, and one that is not positive is refused before any request. Stado Desktop's Sandboxes section has the same operation.
- **`stado sandbox webhook` tells an agent factory about sandbox lifecycle events without polling:** `webhook create <url> --event <event>[,<event>...] [--name]` registers a public HTTPS endpoint for `sandbox.ready`, `sandbox.error`, `sandbox.archived`, `sandbox.hydrated`, `sandbox.degraded` and `sandbox.recovered` and prints its signing secret, which Boat never shows again; `webhook list` and `webhook show <webhook>` read endpoints without their secrets; `webhook update <webhook> [--url] [--event] [--name]` changes one and keeps its secret; `webhook rotate <webhook>` prints a new secret; `webhook delete <webhook>` removes one and its queued deliveries. An empty `--name` or `--url` is refused by name, and an update naming nothing is refused by the client. Stado Desktop's Sandboxes section has the same operations.
- **`stado sandbox snapshot share` hands a prepared disk to another Boat account:** `snapshot share <name>` makes a secret code, printed only now, with which any Boat account starts a sandbox from that named snapshot through `create --from <code>`, billed to itself; `snapshot shares <name>` lists the codes, active and revoked, without the codes themselves; `snapshot unshare <name> <share id>` revokes one, after which a sandbox from it is refused (`snapshot_not_found`) while those already made keep their copy. Everything on the disk is shared. Stado Desktop's Sandboxes section has the same operations.
- **`stado sandbox` shows and limits what a sandbox's agents spend on AI:** `ai-usage <id> [--days <n>]` prints the requests its agents made through Boat's AI proxy per UTC day, credential and model, with their tokens, errors and cost, and whether it is blocked; `ai-access <id> --state allowed|blocked` lets those requests through or has the proxy refuse them, running or stopped (a sandbox holding real keys is not affected). Stado Desktop's Sandboxes section has the same operations, and its environment and webhook operations now live in their own list beside the per-sandbox ones.
- **`stado sandbox environment repos` finds the repository id `add-repo` takes:** it lists the GitHub repositories Boat can clone, grouped by installation, each with the `databaseId` that `environment add-repo` takes, and the ones already selected; `--query` filters by name, `--sync` reads GitHub again first and `--cursor` reads the next page, and an empty `--query` or `--cursor` is refused by name. Stado Desktop's Sandboxes section has the same operation.
- **`stado service file sync --source-file -`, `stado service declare --file -` and `stado service file fetch --dest-file -` use standard input and output:** a caller holding a secret or a declaration in memory had to write it to a file of its own first, typically under the system temporary directory, so a service's secret stood on the operator host's disk for as long as the call ran, and a caller reading a service's file had to name a local file to receive it. With `-` the content is read from standard input, never written on this host, and carried to the target as a file's would be; `file sync` refuses `-` when standard input is a terminal and refuses empty input naming `standard input`. `file fetch --dest-file -` writes the verified bytes to standard output and nothing else there: it refuses `--json` beside it and a name that matches more than one unit, and a fetch that cannot be believed writes nothing and exits non-zero with its cause. A file source still has to be absolute, a regular file and owner-only unless `--executable` is set. `file sync` no longer refuses a file above a size written into it (1 MiB, 96 MiB executable), a number nothing declared; the channel carries what it is given. `service declare` also states its loopback endpoint through the address type instead of a written address, and refuses a `port` that is no TCP port with the conversion's reason. `service onboarding set --surfaces` takes its surfaces comma-separated or with the flag repeated, no longer as several words after one flag.

### Changed

- **The sandbox provider is Boat, and Stado speaks Boat Public API v1:** Box was renamed Boat, and its legacy API (`ascii.dev/api/box/v1`, `/boxes`) answers with a `Sunset` notice. The provider id is now `boat` (the `box` and `box-ascii` names are gone), its settings are `boat.ttl_seconds`, `boat.release_mode` and `boat.api_url` in the profile with the environment overrides `BOAT_TTL_SECONDS`, `BOAT_RELEASE_MODE` and `BOAT_API_URL` (the `BOX_*` variables are no longer read), and its key is the Skarbiec item tagged `stado:role:cloud-boat`, which a workload grant may not carry. Requests go to `https://boat.dev/api/v1/sandboxes` with Boat's own response types; a deletion carries the confirmation Boat requires and accepts Boat's background deletion; a sandbox Boat cancelled for want of a machine fails its job by name; an account at its active-sandbox limit is refused with both counts; and an answer that echoes the API key has it replaced by `[REDACTED]` before it becomes an error.

### Fixed

- **The object-evidence cleaner says when a link stands in its root's path:** a symbolic link or file in place of a directory on the way to an evidence root was only counted as `root_not_a_directory`, so a root the cleaner never cleans under looked like a quiet pass. It is now also named among the pass's errors with that component's path and the operating system's refusal; the cleaner still does not follow it.

- **Release publication names what a build receipt got wrong:** a receipt that disagreed with its run in any of eleven ways was refused as `release job returned mixed or invalid output`, leaving the operator to diff it by hand. The refusal now names the job and every field that disagrees with both values, an absent artifact with the archive's digest, and a failed status with the failure the receipt states. A release job that failed without an error now says it ended in its state without one, instead of printing the state as the error.

- **`stado resources rationalize` says why a source was not read whole:** the source table's `ERROR` column printed only an `error` field and left every other cell blank, so a source blocked because the queue is on device-local storage, or one unsupported by this build, showed no cause and no remedy. The column is now `WHY`: empty for a source read in full, and otherwise the error, reason and `remedy:` the source gave, or `not reported` when it gave none.

- **`stado release staged activate` says why it stopped:** an env file whose bytes did not arrive intact was reported as one that "could not be read (read)", a staged installer that failed was never checked and the run went on to compare versions, and a run that did not report the runtime link after the settle window was refused as one "put back to" an empty link. The env-file refusal now carries the fetch's own report (missing is not found; unreadable or corrupted is an infrastructure failure), a failed installer is refused with its exit and last error line, and a missing link reading is named as missing.

- **`stado host user create` leaves an omitted display name to the host and reports a failure whole:** an omitted `--full-name` was replaced by the username, the display name and shell were refused past a 255-character limit nothing declared, and a failing host's detail was cut to its last 2000 characters. `--full-name`, like `--shell`, now leaves an omitted value to the host's account tool (`sysadminctl` or `useradd`), the account tool refuses a length it does not take in its own words, and the detail is its whole stderr, else stdout, else the exit status. A selected host without an SSH destination is refused instead of being reported with a blank one.

- **The host beacon names a systemd trigger it could not read:** reconciling a oneshot's lifecycle skipped a trigger (its timer) whose `systemctl show` could not run or failed, so a unit whose timer systemd could not answer for stayed unscheduled with no trace why. Each such read is now listed on the unit as `triggers_unread` with its cause, beside `lifecycle_unread`.

- **`stado credentials try-unlock` says why the host Keychain or `key-doctor` failed:** the remote program threw away the stderr of `security` and `skarbiec key-doctor`, so a Keychain that could not be read was taken for one with no phrase, and a `key-doctor` that answered without a report was quoted without its errors. A missing `skarbiec-vault` item (`security` exit 44) is still no failure; any other Keychain failure is said on stderr with its status and words, and refuses a `--keychain-only` run with that cause. `CommandOutput::succeeded` is the name for a command that exited with the platform's success status, and the callers move to it from `ok`.

- **A RunPod pod whose launch stamp does not read is refused:** the `STADO_LAUNCHED_AT` stamp Stado writes into a pod's environment was read as no launch time when it did not parse, so the reaper refused the pod as one of unknown age without saying the stamp was the cause. It is now refused naming the stamp and the parser's reason.

- **`stado identity verify` says why this machine's Apple accounts could not be read:** a `defaults read MobileMeAccounts` that could not run or ended in failure left the binding unknown without a word. It now says on stderr which of the two happened, with `defaults`' own words, before the binding is reported unknown.

- **`stado web declare` carries a unit's host, port and consumer only for a unit:** a declaration took an empty host, port `0` and an empty consumer whenever clap had not supplied them, trusting that only a redirect reached that path. What answers a hostname is now one of a redirect, an upstream service or a unit, and a unit lacking one of the three is refused with `a unit declaration needs --host, --port and --consumer`; a mount whose owner cannot be looked up because the declared web products cannot be read is refused naming their problems instead of reading as no owner.

- **A workload plan flag that is not a boolean is refused:** `fresh_profile`, `allow_login`, `defer_fills`, `prefill_all`, `windowed`, `repair` and `apple_only` named with anything but `true` or `false` (`"yes"`, `1`) were read as off, dropping what the plan asked for. They are now refused with `workload plan <field> must be true or false, not <value>`; a flag the plan does not name stays off. A `login_item` is checked by the grammar Weles identifiers share and must begin with a letter or digit, and an unmet placement is recorded with the reservation the kind declares rather than a reservation of nothing.

- **`stado repair` prints a step's missing name, status or proof as not reported:** a step report without its name printed `repair`, without its status `reported`, and without its proof `not declared`, each a word the step never gave. Absent fields now read `not reported`. The proof each declared step must show is now kept beside the repair declarations.

- **`stado space work-root` says what `systemctl` and `df` said when they fail:** the host program threw their stderr away, so a `systemctl` that could not read the unit's account fell back to the SSH account, and a `df` that failed left an empty device that was refused as `not a device-backed filesystem`. Each failure is now refused with the command's own words, and the path's filesystem is read with one `df` instead of three.

- **A rented machine the vendor reports without a name is no agent, and the vendor answers that do not say what a machine is are refused:** twelve GPU cloud adapters read a machine reported without a name as named `""`, so a machine whose guest is known by its name got the reference `@<id>`. A machine's name is now absent when the vendor reports none: it is not counted as a fleet agent, and a reference to it is refused naming the machine. A RunPod pod naming no GPU type, a Vultr instance without a readable `status` or `power_status` (read as running before), an Oblivus lifetime that is not a number of minutes, and an Oracle URL without a host are refused with the vendor's answer instead of standing a value in; Scaleway's listing starts at its documented first page.

- **Every count Stado keeps adds one item the same way:** counts of audited objects, schedule fires, job yields, scanned and eligible evidence items, and resolver wait keys each spelled the number one in a disguise of their own (`NonZeroU64::MIN.get()` and the like), and a job's yield count saturated while the others did not. They now go through one `primitives::tally` (`Tally::tally` for a count, `draw` for a shared counter), which states the step once and stops a full count at its maximum instead of wrapping. `stado quota show` prints its grand total when a second provider answered, as before, without a spelled-out number.

- **Stado's journeys read a process's success from the process:** twenty-four journeys refused to run unless the caller stated in `STADO_TEST_SUCCESS_EXIT` what a successful process exits with, and compared every status to that number. They now share `tests/native/process.mjs`, whose `exitedCleanly` reads a started, unsignalled process with the platform's success status, `exitedRefusing` a process that ended with a failure status of its own, and `succeededStatus` a recorded exit code; `STADO_TEST_SUCCESS_EXIT` is no longer read anywhere.

- **`stado release doctor` says `not reported` where its report is silent:** a field the diagnosis did not carry printed `-`, a published status row without its detail printed no detail line at all, and a report without its remedy or quarantine lists printed as if there were none. Absent fields now read `not reported`, the missing detail is said, and the remedy and quarantine sections print exactly what the report lists.

- **The vault doctors say what Skarbiec's report left out and why it could not be read:** a recipient without key files printed `(no keygrip)`, a report naming no remedy was refused with a remedy Stado made up, and a key-doctor answer that was not JSON was refused without the parser's reason. The key file now reads `not reported`, a report without a remedy is refused quoting the report, and the unreadable answer names the parse error. `stado vault authority --json` exits with the CLI's declared failure status.

- **`stado resources inventory` says what a source did not report instead of printing blank cells:** a compute source without a provider list printed an empty provider table, and a count, age, holder list or hostname list a row did not carry printed an empty cell, which read as none. The missing provider list is now said in a line of its own, and each missing cell reads `not reported`.

- **The local vault inventory says what an item did not carry and why grants could not be read:** an item without its id, type or update time printed an empty cell and one without its deletion flag printed `false`, and a grant inventory that was not JSON was refused without the parser's reason. Each absent field now reads `not reported`, and the refusal ends with the parse error.

- **`stado release status` refuses a `--limit` it cannot count to and shows a negative run duration as it is:** a `--limit` larger than the platform could count read every recorded run instead, and a run whose recorded end preceded its start printed `0s`. The limit is now refused with `--limit <N> cannot be counted here: <cause>`, and such a duration prints as the negative seconds it is, so a clock that ran behind is visible.

- **`stado quota request list` counts Azure tickets on what each one states:** a ticket that did not say whether it awaits the customer was printed as `N` and counted as awaiting Microsoft. It now prints `not reported`, the summary counts only tickets that state either, and names how many did not. GCP requests without a state, family or region sort ahead of the named ones rather than under an empty name.

- **`stado quota show` and `quota catalog` sum and sort only what the providers gave:** the grand total row looked an accelerator's available count up again in a second map and printed `0` when it was missing, and the GCP catalog sorted a row without its quota id or region as an empty name. Totals and available counts are now summed together from the rows the providers returned, rows without a quota id or region sort ahead of the named ones, and the table rules are as long as their headers.

- **`stado quota ticket reply|escalate` say what a result row did not report:** a provider result without its `ok` field was printed as `N` and counted as a failure, and one without its region as `(no region)`; the two commands kept two copies of the same table. They now print one table, in which a missing `OK` or region reads `not reported` and only rows the provider said succeeded are counted, and a dry-run row says `dry_run → would be replied` or `would be escalated`.

- **`stado overview` names what its fleet lines did not read:** a capacity row the registry maps to no target printed `unmapped` without saying which consumer published it, a target without a name printed `unnamed`, a measurement without a time printed `unstamped`, and a measurement without its capabilities printed nothing after `can do:`. The worker line now names the publishing consumer, and an absent name, time or capability list reads `not reported`.

- **`stado web origin`, `web route publish` and `identity verify` print an absent field the way every other report does:** an origin row without a name printed `(undeclared)`, a read without its elapsed time printed `null ms`, a publication whose server sent no name printed `an unnamed server`, and a binding without a host or identity printed `(no host)`; each kept its own helper besides. They now use the one report-field renderer, so an absent field reads `not reported`, and `web route publish --check` exits with the CLI's declared failure status when the route would change.

- **`stado status` names a job without a recorded submitter as not reported:** a job record written without its submitter showed `?@<host>` in the `SUBMITTED_BY` column, a mark that reads as an account. It now shows `not reported@<host>`, and the rule under the table header is as long as the header instead of a fixed width.

- **`stado host gates` says a figure was not reported or not observed instead of standing a value in:** a capacity publication without its running job count printed `0 running job(s)`, a reservation total it left out printed `0` cores and GiB, a missing core, RAM or VRAM pair printed `-/-`, a reservation field it left out printed `?`, and an uncounted local snapshot number printed `-`. Each now prints `not reported` (a figure the host's publication lacks) or `not observed` (a reading this command could not take). Figures print as the host published them rather than rounded, a waiting job is named by its whole id, and a capacity map that cannot be written out says why instead of printing `{}`.

- **A capacity row that does not state what a hold is judged by is refused instead of read as none:** a host publication without `available_cpu_cores` was read as zero free cores and one without `accepting_jobs` as not accepting, so a workload hold was refused as `has no room` for a reason the host never gave, and a missing reservation count read as none. Such a publication is now refused with `<target> publishes no <field> in its capacity row, so whether the hold fits cannot be judged; update its agent or pick another host with --target`, and a free RAM or reservation count it leaves out prints as `not reported`. `stado capacity list` carries a field the publication lacks as `null` in `--json` and `not reported` in the table instead of `0`, an empty list or `?`; storage listings print an unread object count or update time as `not reported` instead of `?` or an empty cell; and the host scan line says `not reported` instead of `?`.

- **A report field a host did not send reads `not reported` the same way in every command that shows it:** `stado dns set|remove`, `release destinations`, `inference blockers`, `stream` reports, `route capability` and `web status` each kept their own helper for an absent field, and they differed: a value of another type than the helper expected (a port sent as text, a count as a string) printed as `not reported` though the host had sent it. They now share one renderer, which prints text bare, any other value as its JSON, and only an absent or null field as `not reported`. `stado dns set --check` exits with the CLI's declared failure status when the record would change.

- **A committed-source export that tar refuses says why instead of `Broken pipe`:** the export behind `stado quality check` (the pre-push check included), local product builds and pinned Cargo sources wrote the `git archive` of a revision to tar's standard input and stopped at the first write error, so a tar that refused the destination and stopped reading surfaced only as `cannot export <revision>: Broken pipe (os error 32)`. The export now reads tar's standard error while it writes, waits for tar, and refuses with tar's exit status and its own words (`tar could not unpack the committed source of <revision> into <dir>: <status>: <tar's message>`); a write that broke while tar succeeded is named as tar not taking the whole archive.

- **Stado's journeys build in the one workspace and its one lock:** the reaped-read, authority-read, vault-consultation, host-exec Skarbiec and transport-fault journeys were three packages of their own under `tests/`, each with its own `Cargo.lock`, which drifted from the workspace's. They are now `[[test]]` targets of `stado-rs/Cargo.toml` (`cargo test --manifest-path stado-rs/Cargo.toml --test reaped-reads`, and so on), their separate manifests and format gates are gone, and the workspace's format gate covers them. The reaped-read fixture's must-succeed runner is named `succeeded`, and a reaper count that does not read fails the journey instead of reading as no reaping.

- **`stado host privacy` refuses a measurement it cannot read instead of standing values in:** a beacon naming no host was attributed to the target asked about, a measurement without a Documents path judged each grant against an empty home, a program the measuring process could not name became `the Stado executable`, and a folder entry with no state this Stado reads became `not measured`. Each is now refused naming what the beacon lacks, and a program that could not be named prints with the operating system's reason.

- **A database declaration override that is not text is refused:** a `WC_DATABASE_API_DATABASES` set to something that is not text was read as unset, so the config file's declarations stood in for the ones the process was given. It is now refused as `WC_DATABASE_API_DATABASES cannot be read: <cause>`. Stado's run engines and the scope word are read and written through the enum's own serde names.

- **`stado credentials backup audit` says why a pair stayed unproven and why a deletion was refused:** the host half now carries those errors, and the report prints each as `unproven: <path>: <why>` and under `refused:` as `<path>: <the unlink error>` (`unproven` and `reclaim.delete_failures` in `--json`). A class the pass printed no row of reads `none` instead of zero, and in `--json` a namespace root read and found empty is an empty list while a root whose inventory never ended is null, where both read as an empty list before.

- **The backup audit's host half says why it could not read a file:** a file whose metadata or content could not be read was reported only as `unreadable`, a same-size pair whose content could not be hashed was classified `same_size_unproven` with no reason, a refused deletion dropped the unlink error, and a deleted twin's size was counted as nothing when it did not parse.
